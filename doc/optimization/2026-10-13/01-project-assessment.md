# 整体评估与优化计划

评估日期：2026-10-13（Asia/Shanghai）。

## 1. 结论与评估边界

项目已经具备主要业务页面与流程，但页面规范、模块边界和验证机制没有跟上功能增长。应统一信息与视觉规则，整理高耦合模块，清理遗留内容，并恢复可信的自动检查。

本评估基于页面模板、样式、路由、API、状态管理、引用关系、文档与本地自动检查。没有修改业务代码，也没有进行浏览器视觉验收或后端联调。源码中的布局风险需要在真实页面和真实数据下验证，不能写成已经复现的视觉缺陷。

可延续的基础：Vue 3、Element Plus、Pinia 及 Vite 的基础架构；终端模块已有的组件与 composable 分离；已有的请求竞态保护、失败后保留快照、部署结果未知时防重复操作等业务保护。

## 2. 页面与信息设计

### 2.1 缺少统一的视觉与布局规则

终端列表使用渐变 Hero、大圆角和多层卡片；业务与部署列表接近默认表格；终端详情使用固定高度面板；编辑器与调试台各自维护复杂布局。不同页面的标题、密度、留白、颜色和操作位置缺乏共同规则。

影响：页面观感割裂；每次调整需要逐页处理；局部修补持续产生新样式。

方向：建立紧凑管理控制台规范，统一页头、筛选区、内容容器、状态、表格、表单、空态和响应式行为。视觉效果必须与交互同时纳入规范。

### 2.2 页面问题与调整方向

| 页面 | 源码观察 | 调整方向 |
| --- | --- | --- |
| 终端列表 | Hero 占用首屏；重复功能说明；卡片展示大量底层遥测 | 紧凑页头；名称、在线状态、异常和最近在线优先；详细遥测进入详情 |
| 业务列表 | 名称、ID、用途、环节标签和四个操作竞争注意力；缺少搜索与列表组织 | 名称作为入口；统一规模摘要；用途弱化；次要操作收进菜单；按数据规模设计筛选与分页 |
| 部署列表 | 设备 ID 在两列重复；部署时间重复；逐设备标签随设备数膨胀 | 业务与部署序号、部署状态、安装结果摘要、设备数量、时间为主；逐设备信息展开 |
| 终端详情 | 多种诊断信息同时铺开；固定高度；宽表格位于半宽区域 | 关键状态集中；概览、遥测、连接历史、运行记录按任务组织；数据表使用足够宽度 |
| 业务编辑器 | 草稿、界面资源、环节、参数、校验和部署在同一页面密集组合 | 稳定的选择区与属性区；设置和资源渐进展开；校验定位明确 |
| 调试台 | 控制、灯光、界面、音频、图片、画板与结果同时呈现 | 按任务组织操作；保持设备上下文和结果区稳定；统一滚动与会话行为 |
| Dashboard | 只有欢迎语和菜单说明 | 有总览需求则展示可行动信息，否则默认进入主要工作页 |

### 2.3 文案与内容冗余

删除重复标题或控件含义的说明，例如“查看所有已认领和未认领的终端设备，监控在线状态和遥测数据”，以及 `SDUI / BUSINESS` 等无业务用途的装饰标签。

保留会影响决策和恢复操作的信息：未保存修改、离线等待、失败原因、当前显示旧快照、部署结果未知、凭据仅返回一次。说明应短且就近，详细帮助按需展开。

技术 ID、协议枚举、原始 JSON 默认弱化，通过复制、展开或详情访问。不得用文案简化掩盖状态差异。

## 3. 模块结构与维护成本

### 3.1 高耦合文件

以下规模为评估时快照，行数用于定位审查重点，不作为机械拆分标准。

| 文件 | 行数 | 集中的职责 |
| --- | ---: | --- |
| `src/views/sdui/business/BusinessEditor.vue` | 1,658 | 草稿、引用更新、资源、字段表单、校验、保存、部署、路由状态 |
| `src/views/sdui/debug/DebugWorkbench.vue` | 1,214 | 设备上下文、请求目录、历史、音频、图片处理、画板、传输会话 |
| `src/views/sdui/terminal/components/DeviceCard.vue` | 629 | 列表展示、遥测计算和大量装饰样式 |
| `src/api/business.ts` | 661 | 业务、目录、部署、运行的类型、解析、请求 |

局部需求通常跨越多个职责。例如重命名页面或环节，会影响触发器、跳转、资源引用、选择状态与校验定位。当前直接修改共享响应式对象的逻辑较多，修改者需要理解整页，易漏改关联行为。

### 3.2 建议边界

| 层次 | 职责 | 不应承担 |
| --- | --- | --- |
| 页面与展示组件 | 布局、选择、输入与动作事件、状态呈现 | HTTP 细节、协议解析、跨对象引用维护 |
| 业务 composable | 加载、草稿生命周期、保存、部署、请求竞态与清理 | 大量展示标记、底层编码算法 |
| 领域函数 | 重命名、删除、引用更新、校验、序列化 | Vue 组件依赖、消息弹窗、路由跳转 |
| API 边界 | 请求、响应解析、明确类型与错误 | 页面状态和布局决策 |

编辑器按草稿状态、引用操作、资源编辑、校验定位、部署流程拆分。调试台按设备上下文、请求、历史、音频、图片、画板和传输会话拆分。

不能只拆模板却把全部状态留在父组件；不能以一个巨型 composable 替代巨型页面；不能为减少重复建立参数过多的万能页面组件。

### 3.3 重复逻辑与类型边界

- `useDeviceList` 与 `useDeviceDetail` 重复实现遥测结构校验，应归并到设备领域解析。
- 多页面重复实现响应解包、记录判断、时间格式化和状态标签。
- 请求序号、路由代次、旧快照保留机制分散，应统一生命周期规则，保留已有保护。
- Axios 拦截器返回业务响应体，调用方类型与运行时结构存在偏差；自定义 `sdui` 请求配置缺少准确类型。
- `AgentAccess.vue` 直接使用通用 request，API 行为尚未完全集中。
- `resetRouter` 通过给 `router.matcher` 赋值重置，与现有动态 `addRoute` 管理方式不匹配，应明确登记和移除动态路由。
- 全局样式存在 `--ep-*` 引用与现用 Element Plus 样式混用，需统一主题变量和实际生效路径。
- 编辑器存在后追加 CSS 覆盖前面规则的情况；调试台大量代码压在超长单行，增加审查与修改难度。

## 4. 闲置与废弃代码候选

静态引用检查结合了路由和全仓检索，但不等于完整运行时证明。`import.meta.glob`、自动组件导入和声明文件需要单独核对。

| 候选 | 已知事实 | 后续处理 |
| --- | --- | --- |
| `src/views/datasource/`、`domain-docs/`、`file-manager/`、`knowledge/` 及各自 API | 当前路由无入口；四个页面合计约 2,643 行 | 确认产品去留；退役时整条功能链删除 |
| `src/utils/sdui-normalize.js` | 未发现生产引用 | 优先核对后删除 |
| `src/api/artifact.ts` | 未发现生产引用，且 `RunArtifact` 类型未定义 | 确认用途后删除或重新设计 |
| 三个 `@vue-flow/*` 依赖、`echarts`、`mockjs` | 未发现源码或构建脚本使用 | 核对后从依赖和锁文件移除 |
| `src/styles/element/index.scss`、`dark.scss` | 未接入现有样式入口 | 删除闲置主题方案，统一实际主题 |
| `user` store 的 `changeRoles` | 未发现调用，含演示性 `${role}-token` 生成逻辑 | 清理演示入口与逻辑 |
| Navbar 中原后台模板项目及文档链接 | 仍指向模板资源 | 删除或替换为项目真实入口 |

`TelemetryTable`、`SceneRuntimePanel`、`ScrollingText`、`jszip` 有实际调用，不列为废弃项。store 自动加载文件和 TypeScript 声明文件不能因缺少普通 import 判定为无用。

清理时同步检查路由、API、类型、图标、资源、依赖、测试与文档；已退役功能不保留隐藏旧入口。

## 5. 自动检查基线与 AI 修改失败原因

### 5.1 2026-10-13 初始检查

| 检查 | 命令 | 结果 |
| --- | --- | --- |
| 回归测试 | `node --test scripts/*.test.mjs` | 11 个通过，7 个失败；包含终端测试文件初始化失败 |
| 类型检查 | `./node_modules/.bin/vue-tsc --noEmit --composite false --incremental false -p tsconfig.app.json` | 65 个类型错误；编辑器 29 个、调试台 16 个 |
| 静态检查 | `./node_modules/.bin/eslint src scripts --format json` | 4,708 个错误；调试台 3,807 个，大量为格式规则 |

类型检查关闭 composite 与 incremental 仅用于本次无输出检查，未修改配置。未运行带 `--fix` 的 lint，也未运行构建、浏览器验收或后端联调。错误数量不等同于功能缺陷数量。

### 5.2 测试与实现脱节

部分测试从 Vue 文件按函数名提取源码，再手工补齐外部变量执行：

- 部署测试没有跟上编辑器新增的 `deploymentValidation` 依赖。
- 部署监控测试的手工环境与当前 `loadRecords` 依赖脱节。
- 终端测试仍提取已不存在的 `moveBusinessOrder`、`saveBusinessOrder`。

这种测试依赖内部函数名称和闭包细节，重构易破坏测试，又无法验证完整用户行为。失效测试也不能直接证明生产功能失败。

### 5.3 改进方向

1. 领域函数直接导入测试；composable 验证竞态、失败恢复、路由切换和清理。
2. 组件测试围绕用户可观察行为；少量浏览器测试覆盖创建、编辑、部署、查看结果。
3. 建立不自动修复的检查命令，类型检查纳入标准流程；现有构建仅运行 Vite，不能替代类型检查。
4. 恢复可读格式，按职责拆分；区分格式整理与行为修改，便于审查。
5. 统一 API 和领域模型，避免大量 `any` 掩盖契约漂移。
6. 更新验收文档，删除过期功能叙述；验收记录保持真实，不能由构建结果推断浏览器通过。

## 6. 实施顺序与完成标准

| 阶段 | 优先级 | 工作 | 完成标准 |
| --- | --- | --- | --- |
| 范围与验证基线 | P0 | 确认无入口模块去留；修复失效测试、类型边界与检查配置 | 后续改动具备可信反馈；候选有明确处置结论 |
| 统一规范 | P0 | 信息、视觉、布局、组件、交互与验收规则 | 形成一份可直接实施的规范，避免逐页自由发挥 |
| 列表样板 | P1 | 业务列表、部署列表及必要公共组件 | 两页按同一规范实现，覆盖加载、失败、空态与长内容 |
| 终端页面 | P1 | 列表密度、详情任务组织、固定高度和窄屏布局 | 列表可扫描，详情可定位；诊断信息按需访问 |
| 复杂工作台 | P1 | 编辑器、调试台分层及布局重整 | 局部需求可局部修改、独立验证；保护机制保持有效 |
| 收尾验收 | P2 | 删除退役链路、闲置依赖和样式；同步文档 | 无长期双轨实现；关键路径完成浏览器和联调验收 |

规范建设可与验证基线整理并行推进，但不能把失效检查带到大规模功能重构之后。先完成两个列表样板再推广，避免同时改动所有页面导致评估困难。

## 7. 待确认与待验证事项

- 数据源、领域文档、文件管理、知识库四个无入口模块是否仍属于产品范围。
- Dashboard 是否需要成为真实总览。
- 列表规模和搜索、分页、排序能力是否需要后端支持；禁止把当前页过滤伪装为全量搜索。
- 调试台会话、设备切换及离开页面的实际业务约束。
- 真实数据下的视觉、长内容、滚动、键盘操作与窄屏验收。
- 当前手工验收清单中旧部署步骤、事件流描述与实现的具体差异。
