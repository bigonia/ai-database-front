# 统一页面规范

版本：v1。建立日期：2026-10-13（Asia/Shanghai）。

本规范是后续页面改造的实施与验收基线，当前尚未落到业务代码。覆盖信息架构、视觉、布局、组件、交互、响应式和可访问性。视觉效果必须纳入规范，并通过变量、组件和浏览器验收共同约束。

## 1. 设计目标与适用范围

- 管理页面以快速扫描、定位对象、判断状态和执行操作为目标。
- 采用浅色、克制、清晰的控制台风格；中性色组织内容，蓝色表达主操作，状态色表达结果与异常。
- 默认中等偏紧凑密度，减少无意义装饰和重复信息；复杂工作台保留必要操作空间。
- 在现有 Element Plus 基础上统一主题和组合组件，不另建一套基础控件。
- 所有页面共用信息与视觉规则；列表、详情、编辑器、调试台允许采用不同任务布局。
- 首轮以浅色主题为验收范围；后续主题扩展必须使用同一语义变量体系。

## 2. 信息与文案规则

### 2.1 内容取舍

| 信息 | 规则 |
| --- | --- |
| 页面标题 | 简短业务名称，如“终端管理”“业务”“部署” |
| 页面说明 | 默认不展示；仅在存在操作边界或必要上下文时出现 |
| 英文装饰标签、重复介绍 | 不展示 |
| 数量 | 放在标题旁或对应筛选项，不为无决策价值的数量单独铺大卡片 |
| ID | 次要信息；需要追踪时可复制；不重复占据多列 |
| 状态 | 中文短标签；同一含义跨页面使用同一名称和色彩 |
| 帮助 | 字段就近短提示；长说明进入帮助、Popover 或展开区 |
| 风险与恢复 | 未保存、离线等待、旧快照、结果未知、凭据仅显示一次等必须保留 |

空值统一用 `—`；已知为零显示 `0`；未知状态显示“未知”，不能自动映射为成功、离线或空数据。时间使用统一格式，技术 ID 使用等宽字体。列表可显示 `YYYY-MM-DD HH:mm`，详情补齐秒和必要时区；相对时间提供完整时间提示。

### 2.2 信息层级

1. 首要：对象名称、关键状态、当前主任务。
2. 次要：规模、归属、更新时间、操作上下文。
3. 详细：设备明细、协议字段、原始数据、历史过程。

同一信息在列表行内原则上只出现一次。详细内容通过展开或详情访问；对用户输入的长描述不能以固定高度截断后不给访问方式。

## 3. 视觉基础

下列为统一默认值。实现时集中定义为 CSS 语义变量，并映射到 Element Plus `--el-*` 变量；不继续混用 `--ep-*`。页面局部样式引用语义变量，避免重复硬编码。色值是设计基线，实际文本与背景组合仍需验证对比度。

### 3.1 颜色

| 语义 | 建议变量 | 默认值 | 用途 |
| --- | --- | --- | --- |
| 页面背景 | `--app-bg` | `#f6f8fb` | 应用内容底色 |
| 内容表面 | `--app-surface` | `#ffffff` | 表格、卡片、弹层 |
| 次级表面 | `--app-surface-muted` | `#f8fafc` | 表头、只读区、轻分组 |
| 主文本 | `--app-text` | `#182230` | 标题与正文 |
| 次级文本 | `--app-text-secondary` | `#475467` | 摘要、说明 |
| 辅助文本 | `--app-text-muted` | `#667085` | 时间、ID、次要信息 |
| 边框 | `--app-border` | `#e4e7ec` | 容器和分隔 |
| 主色 | `--app-primary` | `#2563eb` | 主按钮、链接、选中 |
| 主色浅底 | `--app-primary-soft` | `#eff6ff` | 选中背景 |
| 成功 | `--app-success` | `#15803d` | 成功、在线 |
| 警告 | `--app-warning` | `#b45309` | 等待、部分异常 |
| 危险 | `--app-danger` | `#b42318` | 失败、危险动作 |

常规内容容器不使用装饰性渐变。状态色只用于标签、图标、必要边线或轻背景，不给整页或整行大面积染色。主操作保持蓝色，不因部署、保存等动词更换主按钮颜色。

### 3.2 字体

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 22px / 30px | 600 |
| 区块标题 | 16px / 24px | 600 |
| 正文、表单、表格 | 14px / 22px | 400 |
| 辅助信息、ID | 12px / 18px | 400 |

中文采用系统字体栈，ID、代码使用系统等宽字体；数字计数可用等宽数字。正文不低于 14px，辅助信息不低于 12px。不可用浅灰小字承载关键状态或错误原因。

### 3.3 间距、圆角和阴影

- 间距阶梯：4、8、12、16、24、32px；局部特殊值必须有实际布局原因。
- 页面内边距：桌面 24px，窄屏 16px；页内主要区块间距 24px，紧密关联内容 12–16px。
- 控件间距 8px；表单字段间距 16px。
- 控件圆角 6px，普通内容容器 8px，弹层 12px；状态标签可使用胶囊形。
- 普通内容容器默认无阴影，使用边框或背景区分；浮层使用轻阴影。
- 避免“外卡片包内卡片再包表格”，相邻内容不靠重复边框层层分割。

### 3.4 控件、图标与动效

- 默认输入框与按钮高 32px；较大表单可统一用 36px，不在同一工具栏混用高度。
- 图标统一使用现有图标体系；一般为 16px，与文字间距 6–8px。
- 仅图标按钮必须具备可访问名称和 Tooltip。
- 交互过渡 120–180ms，用于 hover、选中和展开；不添加无任务价值的动画。
- 尊重减少动态效果偏好；焦点样式可见，不能全局清除 outline 后不提供替代。

## 4. 页面布局模板

### 4.1 应用外壳

- 侧栏、顶部导航、面包屑和页面标题各有职责；页面不得重复完整面包屑路径。
- 一级页面使用外壳导航和单一标题；详情与编辑器可使用局部返回入口，避免与外壳面包屑重复。
- 主内容只有一个明确的页面滚动容器。工作台确需分栏滚动时，滚动区域须明确且不会遮挡操作。
- 固定头部、页签与页面 sticky 工具栏共用布局偏移变量，不各自硬编码 `top`。
- 层级顺序统一管理，页面工具栏不能覆盖全局导航或弹层。

### 4.2 列表页面

结构顺序：紧凑页头 → 搜索与筛选 → 必要的状态提示 → 数据区 → 分页。

- 页头左侧为标题及可选数量，右侧为主操作和刷新；不设置 Hero。
- 搜索和高频筛选默认可见，低频筛选按需展开；当前筛选可识别且可清除。
- 容器内表头、行和分页对齐；无需额外包裹多层卡片。
- 搜索范围明确；只过滤当前已加载数据时必须说明，不能表示为全量搜索。
- 分页在界面统一从 1 开始，由 API 层处理后端索引转换；更新页码与数据保持一致。

### 4.3 详情页面

结构顺序：返回与对象名称 → 关键状态及操作 → 摘要 → 任务区。

- 摘要只展示当前判断所需的字段。
- 多种历史数据用 Tab 或分区组织；Tab 状态可通过 URL 表达，保证刷新与返回体验。
- 宽表格优先占满内容宽度；不用固定高度强行对齐内容差异很大的面板。
- 图表可设置合理高度；正文、历史列表和错误说明按内容增长。

### 4.4 编辑器与调试工作台

- 编辑器使用稳定的选择区与属性区；保存状态、校验和主操作位于固定可见位置。
- 资源与业务设置按需展开，不长期抢占主编辑区。
- 调试台按设备控制、界面、音频、图片、画板等任务组织；设备上下文与执行结果保持可识别。
- 若任务切换涉及传输或录音会话，明确完成、取消和保留规则，不允许切换后旧响应污染新任务。
- 每个分栏有明确最小宽度；内容放不下时切换布局，不持续压缩表单。

## 5. 表格与卡片规则

### 5.1 表格

- 表头背景使用次级表面；正文左对齐，数值按比较需要右对齐。
- 单行内容建议 44px 最小行高，双行信息建议 60px；长错误可展开，不任意撑高所有行。
- 默认使用轻分隔与 hover 背景，不依赖强条纹或粗边框增加层次。
- 首列突出对象名称，ID 作为可复制辅助信息；名称可点击进入详情或编辑。
- 状态使用简短标签；多个设备结果在主列表聚合，展开后查看明细。
- 行内操作最多保留两个高频项，低频及危险动作放入“更多”；名称已提供导航时不重复放同义按钮。
- 操作区宽度稳定，必要时固定右侧；窄屏优先减少非关键列。
- 长文本截断必须可查看完整内容，不能把 Tooltip 作为触屏端唯一访问方式。
- 数据为空时只渲染一个空态，使用表格 empty 插槽或统一状态区，避免表格空态与额外 `el-empty` 重复。

### 5.2 卡片

- 卡片适用于视觉识别或少量对象概览；大量同构管理数据优先使用表格。
- 若终端采用卡片，每张突出名称、在线状态、关键异常、最近在线；内存池和碎片率等诊断进入详情。
- 卡片不使用与真实终端画面无关的大面积“屏幕预览”作为主视觉。
- 卡片整块可点击时必须提供键盘等价入口，内部动作不得触发外层导航。
- 网格根据容器宽度自适应；最窄视口不因固定 `min-width` 产生页面横向溢出。

## 6. 交互与状态

### 6.1 操作与反馈

- 每个工作区只有一个视觉主操作；刷新、返回等使用次级样式。
- 保存、部署、认领等异步动作展示忙碌状态并阻止重复提交。
- 删除等不可恢复动作确认时写明对象及后果；普通刷新和可逆筛选不增加确认。
- 表单使用持续可见的标签，placeholder 不能代替标签；错误定位到字段并给出处理方式。
- 未保存离开需要明确保存、放弃或取消路径。
- 操作结果就近展示；全局 Toast 用于简短反馈，不替代页面内持续错误。

### 6.2 数据状态

| 状态 | 显示与行为 |
| --- | --- |
| 首次加载 | 对应区域骨架或 loading，保留布局稳定 |
| 首次失败 | 区域错误与重试；不能显示“暂无数据” |
| 刷新失败且有旧数据 | 保留快照，标记未更新与上次成功时间，允许重试 |
| 成功但无数据 | 业务空态，必要时提供创建或接入入口 |
| 筛选无结果 | 明确无匹配，提供清除筛选 |
| 部分成功 | 展示成功、等待、失败数量及失败明细入口 |
| 操作结果未知 | 明确结果未确认，提供查询入口，阻止盲目重复提交 |
| 无权限 | 清晰说明无权操作或访问，不混为空态 |

旧数据必须绑定原查询上下文。切换设备、业务或筛选后，不能把旧对象数据当作新对象数据展示。所有请求结果检查请求身份或代次；卸载、停用或切换上下文时清理计时器与会话资源。缓存页面停用后的轮询行为必须显式定义。

### 6.3 状态语义

- 在线使用成功色，离线使用中性色；离线是否阻塞由业务规则决定。
- 安装成功、安装中、等待上线、安装失败分别表达，不合并成一个“部署成功”。
- 部署 active/stopped 与设备安装状态分开表达；active 的中文标签须依据后端业务含义确定，不能未经确认等同于“正在运行”。
- 成功、警告、失败同时具有文字或图标，不能只靠颜色。
- 状态文案与映射集中管理，未知枚举不默认为成功。

## 7. 响应式与可访问性

| 内容宽度条件 | 布局要求 |
| --- | --- |
| 宽屏 | 列表充分使用宽度；工作台可分栏；表单不无限拉长 |
| 中等宽度 | 操作允许换行，减少次要列；工作台按最小可用宽度收拢 |
| 窄屏 | 页头纵向排列；关键控件可访问；详情和工作台改为纵向 |

优先依据组件容器宽度决定局部布局，不能只看浏览器宽度而忽略侧栏占用。

验收视口：1920×1080、1600×900、1366×768、1024×768、390×844，同时检查侧栏展开与收起。页面整体不横向溢出；数据表、代码等确需横向滚动时仅在局部容器内滚动。不得通过 `overflow: hidden` 隐藏无法访问的内容。

键盘可完成导航、筛选、表单和主要动作；焦点可见。弹层打开后焦点进入，关闭后返回触发点；复杂弹层不能产生键盘陷阱。普通文本对比度目标至少 4.5:1，大文本和必要控件边界至少 3:1；实际组合逐项验收。

## 8. 首批页面的落地约束

| 页面 | 默认主要内容 | 按需内容 |
| --- | --- | --- |
| 业务列表 | 名称、用途摘要、界面数、环节数、编辑与部署入口 | ID、环节名称清单、部署记录、删除 |
| 部署列表 | 业务与部署序号、部署状态、安装结果摘要、设备数、部署时间 | 逐设备结果、设备 ID、冻结配置、错误详情 |
| 终端列表 | 名称、在线状态、能力同步异常、最近在线 | ID、遥测明细、连接次数、删除 |
| 终端详情 | 名称、在线状态、当前部署或视图摘要、调试入口 | 完整遥测、连接历史、运行历史、原始数据 |

业务搜索、排序和分页若当前 API 不支持，先明确契约再实现；不能编造字段、前端推断权威状态或只对当前页排序却展示为全量排序。

## 9. 代码落地规则

- 主题变量集中维护；Element Plus 主题覆盖统一处理，避免每页大量 `:deep`。
- 共享组件优先覆盖页头、列表工具栏、状态展示、加载/失败/空态和分页约定；经过样板验证再抽象。
- 业务状态映射、API 解析和格式化按领域管理；页面不自行复制协议校验。
- 页面只负责组合；字段表单、资源选择、部署流程等按职责拆分。
- CSS 保持可读，一处定义一种布局规则；修改原规则，清理失效覆盖，不继续在文件末尾堆补丁。
- 不按固定行数机械拆文件；判断标准是职责独立、依赖清晰、可测试、局部修改影响可控。
- 完成模块替换后删除旧组件、旧样式和过期测试，不增加永久兼容开关。

## 10. 页面验收清单

- [ ] 首屏可识别页面对象、关键状态和主要动作。
- [ ] 无重复介绍、装饰标签及重复字段；必要限制和错误说明保留。
- [ ] 字体、颜色、间距、圆角、控件高度符合视觉基线。
- [ ] 对象名称突出；ID、长描述、长错误有完整访问方式。
- [ ] 加载、首次失败、刷新失败、无数据、无匹配状态各自正确。
- [ ] 主操作明确，无重复提交；危险动作有对象与后果说明。
- [ ] 快速切换路由、对象、筛选后无迟到响应污染。
- [ ] 页面和分栏滚动明确，sticky 不遮挡导航、字段或按钮。
- [ ] 所有验收视口及侧栏状态下主要操作可访问。
- [ ] 键盘、焦点、状态文字和实际色彩对比度通过检查。
- [ ] 运行适用的类型、静态、回归及构建检查，区分历史问题和本次结果。
- [ ] 使用真实或明确标记的测试数据完成浏览器验收，留存截图及操作记录。
- [ ] 涉及 API、流程变化时更新契约和手工验收文档。
