# 分步骤实施计划

建立日期：2026-10-13。实施顺序调整：先优化代码结构和维护基础，最后按用户逐页意见调整视觉与交互。每次交给模型一个步骤或其中一个独立职责，不要求一次完成整个阶段。

## 执行基线

- [整体评估](./01-project-assessment.md)用于了解问题，保留为初始快照；实际实施顺序以本计划为准。
- [统一页面规范](./02-page-design-standard.md)作为最终页面改造基线。结构优化阶段保持现有布局与用户行为，不顺手改视觉、字段展示或操作流程。
- 每步先看当前代码和已有改动，不假设评估中的行数、错误数仍然准确。
- 仅修改本步骤必要文件，保留无关改动；替换后清理旧实现，不保留兼容通道。
- 保留功能、必要风险提示、请求竞态保护、旧快照语义和会话清理。不得为通过检查删除仍有效的业务保护、屏蔽规则或滥用 `any`。
- 按领域和职责建立清晰边界，不全仓搬目录，不机械按行数拆文件，不以巨型 composable 替代巨型页面。共享展示组件留到页面改造时按实际重复提取。
- 不新增或猜测后端能力。缺少全量搜索、分页等 API 时记录限制，不把当前页过滤包装为全量能力。

步骤 7 按用户逐页意见实施，不自动批量改造页面。页面顺序、信息取舍和布局由用户逐页确定；明确提出的调整优先于规范中的默认建议。有新的页面任务时在下方执行记录标注页面即可，不维护一套逐页子计划。没有真实后端或浏览器条件时如实标为待验收，不标记全部验收完成。

## 每步验证

1. 运行步骤 1 建立的 typecheck 和无修复 lint，区分已有问题；后续步骤不得引入新的类型或静态检查错误。
2. 运行相关回归测试；涉及业务逻辑则补充真正验证行为的测试，不为纯样式调整增加镜像实现测试。
3. 页面、主题、模块导入或依赖有变动时运行 `npm run build:test`。构建不能替代类型检查和浏览器操作。
4. 结构重构验证现有功能与界面行为没有意外变化；最后的页面改造按用户意见与页面规范验证视觉、状态和响应式。有浏览器条件则保存截图，缺少条件则记为待验收。
5. 结构重构涉及的旧源码提取测试应在对应步骤迁移，不通过补齐更多假闭包变量维持脆弱测试。无关失败只记录，不扩大当前步骤范围。

## 交给快速模型的提示词

每次只替换步骤编号，其余文本可直接复用：

```text
执行 doc/optimization/2026-10-13/03-implementation-plan.md 的步骤 N。
先阅读该计划，按需参考整体评估；页面改造时再详细阅读 02-page-design-standard.md。
只完成本步骤或本次指定的独立职责，不提前做后续步骤，保留无关改动。
步骤 2–6 只做结构和维护性优化，保持页面布局与用户行为；步骤 7 按用户指定页面和意见实施。
不要保留旧通道，不要猜测后端能力，不要为通过检查屏蔽问题。
运行本步适用检查；区分已有失败与新增问题，不能把构建通过写成浏览器验收通过。
结束时仅在计划中勾选本步并追加一行执行记录；未完成则不勾选，写清剩余项。
不要新建额外报告，不改写初始评估。最后简要报告改动、验证和待验收项。
```

若一步仍明显过大，可按该行的独立职责分多轮执行，继续使用同一个步骤编号；完成全部职责后再勾选，不必新增文档或重编计划。
