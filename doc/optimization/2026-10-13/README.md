## 范围与约束

- 初始阶段仅落地文档，后续实施进度见分步骤实施计划。
- 优化覆盖页面设计、信息冗余、模块维护性、测试机制及闲置代码。
- 先优化 API 与领域边界、拆解大文件、整理生命周期和遗留代码；最后按用户意见逐页优化视觉与交互。实际顺序以分步骤实施计划为准。
- 按模块替换并删除旧实现，不保留兼容通道或长期双轨方案。
- 保留无关工作树变更；本次开始时已有未跟踪目录 `.workbuddy/`，不纳入优化。
- 源码评估、自动检查、浏览器验收、后端联调分别记录，不相互替代。

## 维护方式

1. 整体评估保留为初始快照，不随代码变化反复改写。
2. 统一页面规范是设计基线；只有规则变化时才修改，并在末尾追加版本记录。
3. 每步只在实施计划中勾选完成并追加一行结果，不另建日报、模块报告或重复进度表。检查命令、删除项和截图位置可简写在该行；未验证事项必须注明。
4. 清理候选只有在用途、入口和调用核实后才能标记为已退役；无入口不直接等于无业务价值。
5. 页面实现涉及 API 变化时，同步维护 `doc/sdui/` 下的契约与验收文档。
